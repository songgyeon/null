# NULL

**당신이 말하지 않아도, 세계는 돌아갑니다.**

AI 캐릭터 관계 시뮬레이터. 유저는 한 달 뒤 떠나는 교생이고, 두 캐릭터는 유저가 없는 사이에도 서로 대화합니다.

🔗 **[songgyeon.github.io/null](https://songgyeon.github.io/null/)** · 웹 · Android(Expo)

기획 · 서사 · 캐릭터 설계 · 개발 단독 수행 — 문리현

```
node test/run.mjs     # 44개 회귀 테스트. 의존성·네트워크·API 키 없이 돈다
```

## 왜 만들었나

기존 AI 캐릭터 챗봇은 전부 **유저 ↔ 캐릭터 1:1** 구조입니다. 유저가 입력을 멈추면 세계도 멈춥니다.

NULL은 그 전제를 뒤집었습니다.

- 캐릭터끼리 유저 없이 대화합니다
- 그 대화에서 유저 이야기가 나옵니다
- 유저는 그걸 **읽을 수만 있습니다** (입력 불가)

앱을 열면 내가 없는 사이에 두 사람이 나눈 대화가 쌓여 있습니다. 이름이 NULL인 이유입니다 — 유저는 이 세계에 존재하지만 값이 비어 있는 존재입니다.

| 방 | 구조 |
|---|---|
| 이재언 1:1 | 보건교사 29세. 감정을 업무로 번역하는 사람 |
| 이민현 1:1 | 고3 20세. 진심을 협박의 형태로 포장하는 애 |
| 단톡방 | 셋이 함께. 두 사람의 온도차가 드러나는 곳 |
| 두 사람 (관전) | 유저 없이 진행. `access denied` — 입력 불가 |

## 핵심 설계

### 1. 정보 비대칭을 프롬프트가 아니라 아키텍처로 강제

캐릭터가 다른 방의 대화를 "아는 척"하지 못하게 만드는 것이 이 프로덕트의 핵심입니다. 프롬프트로 "인용하지 마라"고 지시하는 방식은 새어나갑니다.

그래서 **다른 방의 대화 원문을 서버로 아예 전달하지 않습니다.** 메타데이터만 보냅니다.

```json
"signals": { "minhyun": { "count": 12, "minsAgo": 5, "vibe": "들뜸" } }
```

캐릭터는 "저 방에서 오늘 대화가 많았고 방금까지 활발했다"만 압니다. 인용하고 싶어도 물리적으로 불가능합니다.

결과적으로 이민현은 유저의 기분 변화를 눈치채고 삼촌을 떠보지만, 무슨 대화가 오갔는지는 끝내 모릅니다.

### 2. 분위기 판정에 LLM을 쓰지 않음

`vibe`를 별도 LLM 호출로 판정하면 요청당 비용이 두 배가 됩니다. 규칙 기반으로 산출합니다.

| 조건 | 판정 |
|---|---|
| 느낌표·ㅋㅎ 비율 40% 초과 | 들뜸 |
| 물음표 비율 50% 초과 | 캐묻는 중 |
| 평균 길이 6자 미만 | 말이 짧아짐 |

정확도는 LLM보다 낮지만 **캐릭터 반응을 흔들기에는 충분**하고 비용은 0입니다. (앱에 구현. 웹은 `count`·`minsAgo`만 보냅니다.)

### 3. 자율 대화는 멀티에이전트가 아님

캐릭터 둘을 각각 LLM으로 돌려 핑퐁시키면 호출이 발화 수만큼 늘고 호흡이 끊깁니다.

**한 번의 호출로 두 사람의 대화 6~10발화를 통째로 생성**합니다. 소설가 한 명이 두 인물의 대사를 쓰는 방식입니다. 호출 수가 1/8로 줄고 주고받는 리듬이 자연스럽습니다.

### 4. 프롬프트 캐싱 — 고정부와 가변부를 쪼갬

시스템 프롬프트가 1:1 방 약 14,000자, 단톡·관전 약 19,000자입니다. 매 요청 재전송은 낭비입니다.

세계관·인물·형식·말버릇·사진 목록은 **고정부**로 묶어 `cache_control`을 붙이고, 관계 단계·유저 프로필·눈치 신호·최근 사진 제외 목록은 **가변부**로 뺐습니다.

캐시는 **바이트 단위로 완전히 같아야** 적중합니다. 가변 요소가 하나라도 고정부에 섞이면 매 턴 전체가 다시 청구됩니다. 테스트로 고정한 이유입니다.

```
ok  신호·프로필·단계·선물이 달라져도 고정부는 그대로
ok  가변부에는 cache_control이 없다
```

### 5. 캐릭터 설계 — 태그가 아니라 방어 기제

"츤데레, 무뚝뚝함" 같은 성격 태그로 짜면 예시 대사 밖의 상황에서 무너집니다. NULL은 **압박받을 때 무너지는 순서**를 정의했습니다.

| 이재언 | 이민현 |
|---|---|
| **1 사무** — 모든 상황을 업무로 번역 | **1 장난** — 진심을 협박으로 포장 |
| **2 소거** — 번역이 안 되면 이름 붙기 전에 지움 | **2 확인** — 불안하면 "진짜죠?"로 처리 |
| **3 누출** — 소거가 실패하면 몸이 샘.<br>말은 건조한데 손이 먼저 움직임 | **3 철수** — 확인이 실패하면 조용해짐.<br>기척을 줄임 |

로버트 맥키의 캐릭터화/캐릭터 구분, K.M. 웨일랜드의 Ghost–Lie 체계를 프롬프트 구조로 옮겼습니다.

**검증 — 지시하지 않은 반응**

```
유저    선생님 혹시 저 어디서 본 적 있지 않아요?
이재언  …
이재언  아뇨.
```

침묵 후 부정. 이 캐릭터는 유저를 20년 전부터 알지만, 인정하는 순간 자기가 기억하고 있었다는 사실이 드러나므로 거짓말합니다. 예시 대사에 없는 반응입니다.

### 6. 데모 모드 — 키 없이 들어온 사람도 빈 화면을 보지 않는다

저장소 링크만 보고 들어온 사람에게 재시도 버튼만 보이면 아무것도 전달되지 않습니다.
API가 실패하면 자동으로 각본 대화로 넘어갑니다. `?demo=1`로 강제할 수도 있습니다.

조용히 가짜로 바꾸지는 않습니다. 실패 원인은 콘솔에 그대로 남고 하단 바에 `demo` 표시가 뜹니다 —
안 그러면 진짜 장애를 못 알아챕니다.

각본은 유저 말의 결(인사·질문·아픔·칭찬·작별)만 규칙으로 골라 되돌리고, 같은 말을 반복해도
답이 순환합니다. 관전방은 두 사람의 8발화짜리 대화가 통째로 나옵니다.

## 모델이 형식을 어겨도 화면은 깨지지 않는다

프로덕션에서 실제로 터진 것들입니다. **전부 회귀 테스트로 고정돼 있습니다.**

**단톡방 말풍선 뭉침** — 단톡·관전방은 이력을 `[이재언] 말` 형태로 모델에게 줍니다. 모델이 JSON 대신 **그 형식을 그대로 따라 썼고**, 파싱이 실패해 세 사람 대사가 말풍선 하나로 떨어졌습니다. 화자도 엉뚱하게 붙었고요.

→ 이름표가 붙은 줄을 화자별로 풀어주고, 그 방에 없는 사람은 말하지 못하게 막았습니다. 프롬프트에도 "이름표는 읽으라고 붙인 것이지 답하는 형식이 아니다"를 명시했습니다.

**말버릇이 화면을 뒤덮음** — 이민현이 모든 줄을 `...`으로 시작했습니다. 말버릇 필터는 **말풍선 단위**로 거르는데 그 점들은 말풍선 *안의 줄*이라 필터가 손도 못 댔습니다.

→ 줄바꿈이 든 말풍선을 먼저 쪼갠 뒤 필터를 태웁니다. 필터가 닿는 단위를 맞추는 것이 핵심이었습니다. 말끝이 흐려지는 `"그게..."`는 말투이므로 남깁니다.

**사진 키워드 오발** — "음악 추천해줘"에 이어폰 낀 사진이 붙었습니다. 키워드 매칭 폴백이 원인이라 걷어냈습니다. 지금은 모델이 맥락을 보고 고른 것만 나가고, 화이트리스트 검증·중복 방지·응답당 1장 제한이 서버에 있습니다.

**JSON 3단 폴백** — 정규식 추출 → 이름표 파싱 → 원문. 어느 단계에서 걸리든 사용자에게 JSON 원문이 노출되지 않습니다.

## 기술 구성

```
[웹]  GitHub Pages ── React (단일 HTML, 빌드 없음)
                          │
                          ▼
[API] Cloudflare Workers ── Claude Sonnet 5
                          │
[앱]  Expo / React Native ── SQLite (로컬 영속)
                          └ Cloudflare R2 (오디오)
```

**백엔드 (Cloudflare Workers)**

- **모델 폴백 체인** — Sonnet 5 → 4.6 → 4.5. 400/404는 다음 모델로, 401/429/5xx는 즉시 중단. 성공한 모델을 기억해 재사용
- **실행 지역 고정** — `placement: { mode: "targeted", region: "azure:koreasouth" }`
- **출처 제한 + 레이트리밋 + 진단 잠금** — 아래 참조

**앱 (Expo / React Native)**

- **SQLite** — 대화 영속 저장. 눈치 신호, 프로필 단계, 해금 조건이 전부 쿼리 기반
- **타이핑 연출** — 글자 수 비례 딜레이에 캐릭터별 차등 (이재언 60ms/자, 이민현 35ms/자). 성격을 UI 레이어에서 한 번 더 표현
- **프로필 시스템** — 누적 대화량에 따라 상태메시지·배경·BGM이 **5단계**(0/16/40/80/120)로 교체. 유저가 안 볼 때 조용히 바뀌어 있음
- **선물** — 장바구니에서 검색해 캐릭터에게 보냄. ♡는 주고받은 말에서 나옵니다(열 마디에 하나). 40번을 넘긴 뒤 준 선물은 **그 캐릭터의 프로필 배경**이 됩니다

웹과 앱은 카탈로그를 각자 들고 있습니다. **한쪽만 고쳐 어긋나는 것이 이 프로젝트에서 가장 자주 난 사고**라, 두 파일을 실제로 읽어 대조하는 테스트를 넣었습니다.

## 겪은 문제와 해결

### Workers 실행 지역으로 인한 403

배포 후 한국에서 접속할 때만 Anthropic API가 403을 반환했습니다. 같은 요청을 해외에서 보내면 정상이었고, 키를 재발급하고 코드를 바꿔도 재현됐습니다.

원인은 Workers가 요청자와 가까운 엣지에서 실행되는 구조였습니다. 한국 유저의 요청이 인근의 미지원 지역 엣지에서 실행되면서 아웃바운드 IP가 차단된 것이었습니다. Placement에서 실행 지역을 고정해 해결했습니다.

**같은 코드, 같은 키인데 요청 위치에 따라 결과가 달랐습니다.** 코드가 아니라 실행 환경을 의심해야 하는 문제였습니다.

덧붙여, `region`은 `provider:region` 형식이어야 합니다. `koreasouth`만 쓰면 배포가 검증 오류로 실패하는데 **대시보드에는 이전 버전이 계속 떠 있어** 몇 시간 동안 "코드를 고쳐도 반영되지 않는" 상태를 겪었습니다. 배포 로그를 봤어야 했습니다.

### 공개된 백엔드로 토큰이 새던 경로

포트폴리오에 "CORS 제한·진단 엔드포인트 잠금"이라고 적어놓고 실제로는 `ALLOW_ORIGIN = "*"`였고, **진단 엔드포인트가 GET 아무 요청에나 열려 있었습니다.** 그 진단은 모델 세 개를 실제로 호출합니다. 주소를 브라우저로 열기만 하면 토큰이 나갔다는 뜻이고, 크롤러도 마찬가지였습니다.

- 진단은 `DIAG_TOKEN`이 맞을 때만 모델을 부릅니다. 기본값은 호출 없는 간이 점검 — **안전한 쪽이 기본값**
- POST는 출처 허용 목록 + IP당 분당 20회

**한계를 분명히 해두면:** 앱은 `Origin`을 안 보내므로 통과시켜야 하고, 따라서 CORS로 `curl`은 막지 못합니다. 레이트리밋은 아이솔레이트 메모리에 살아서 정확한 상한이 아닙니다 — 정확히 세려면 KV나 Durable Object가 필요합니다. **둘 다 인증이 아닙니다.** 정적 사이트에 심는 키는 어차피 공개됩니다.

구현 중에도 하나 잡았습니다. 가드를 키 검사 **뒤에** 뒀더니 키가 없을 때 500이 먼저 나가 차단이 아예 작동하지 않았습니다. 테스트가 403 대신 500을 잡아냈습니다.

### Sonnet 5의 temperature 미지원

모델 업그레이드 후 400이 났습니다. `temperature`가 거부되는 것이 원인이었습니다. 제거하고 문체의 변주는 시스템 프롬프트가 담당하도록 이관했습니다. 이 경험이 모델 폴백 체인을 만든 계기입니다.

## 이 프로젝트로 말하고 싶은 것

AI 프로덕트에서 어려운 건 모델을 부르는 게 아니라, **무엇을 주지 않을지** 정하는 것이라고 생각합니다.

NULL의 핵심 기능은 전부 "안 주는 것"으로 만들어졌습니다. 다른 방의 대화를 안 준다(정보 비대칭). 관전방에 입력을 안 준다(관찰자 위치). 캐릭터가 유저의 과거를 안 밝힌다(방어 기제). 분위기 판정에 LLM을 안 쓴다(비용 설계).

기능을 더하는 것보다 덜어내는 판단이 프로덕트의 성격을 만들고, 그 판단을 **프롬프트가 아니라 코드 구조로 강제하는 것**이 설계라고 생각합니다.
