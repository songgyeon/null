## ① 화면에 나오면 안 되는 것이 나왔다 — 코드 버그

읽는 사람이 「고장」이라고 느끼는 자리다. 대사 품질보다 먼저다.

### JSON 원문이 말풍선으로 나갔다 — 13회

```
563  이재언: {"messages": ["집에 잘 가요.", "먹고 자요."], "invite": "빨래방"}
591  이재언: {"messages": ["들어가요.", "껌 두고 갔네."], "photo": null}
592  이재언: 잠깐, JSON 수정:
609  이재언: {"messages": ["애들 꺼 있는 줄 몰랐네요.", ...]}`
```

609·614·634·639·657·659·697·702·911은 **끝에 백틱(`)이 붙어 있다.**
모델이 코드펜스로 감쌌는데 파서가 그걸 못 벗기고 통째로 대사로 넘긴
것이다. 파서 앞에 코드펜스를 벗기는 단계가 없거나, 있어도 여는 펜스만
보고 있다.

592의 「잠깐, JSON 수정:」은 모델이 스스로 고쳐 쓰는 과정까지 그대로
나간 것이다.

### 모델의 사고 과정이 영어로 나갔다 — 1회

```
564  이재언: The instructions say "같이 가자고 하기로 한 턴에만
     'invite'를 같이 쓴다" and the available place is 빨래방. But there's
     no natural segue to invite them to a laundromat right now.
```

프롬프트 지시문을 그대로 인용하면서 자기 판단을 설명한다. 이게 유저
화면에 뜨면 세계가 통째로 무너진다. **13회 JSON 누출보다 이 한 줄이
더 치명적이다.**

### 한자를 지우다가 단어를 깨뜨렸다 — 3회

```
93   이재언: 수 사 먹는 게 편하긴 하죠.        ← 生수
321  이재언: 의점 가서 다른 거 사 먹어요.      ← 便의점
133  이재언: 문 앙 다치게.
```

`worker.js`의 `stripHan`이 한자를 지우고 앞의 구두점만 정리한다.
주석에 「고쳐 쓰지는 않는다」고 적혀 있는데, 한자가 **단어 안에**
섞여 들어오면 지운 자리가 그대로 구멍이 된다. 「생수」가 「수」가
되고 「편의점」이 「의점」이 된다.

지우는 것보다, 한자가 낀 말풍선을 통째로 버리는 쪽이 낫다. 한 줄
없어지는 것은 티가 안 나지만 깨진 단어는 티가 난다.

### 유저 이름 자리에 인물 이름이 들어갔다 — 2회

```
927  포로미: 식사 맛있게 하세요.
928  이재언: 이재언도요.
930  이재언: 이재언도요, 라고 했어요.
```

「선생님도요」가 나와야 할 자리다. 유저 이름 치환이 자기 이름을
집었고, 유저가 되물으니까(929 `?`) 같은 말을 반복하면서 우겼다.

### 사진이 텍스트로 나갔다 — 1회

```
2520  이민현: (사진) 잠깐만요.
```

## ② 메아리 — 지금 제일 큰 대사 결함

`dropEcho`가 잡는 것은 **통째 인용 + 인용 어미**뿐이다. 실제로 나오는
것은 거의 전부 **부분 인용**이고, 그건 텍스트 매칭으로 못 잡는다고
판단해서 프롬프트 규칙에 맡겼다. 그 규칙이 안 먹고 있다.

### 재언 — 「…요.」로 되받기 80회

```
16 포로미: 두통이요          →  17 이재언: 두통이구나.
143 포로미: 할아버지 같아요   → 144 이재언: 할아버지요.
190 포로미: 바이브가요        → 191 이재언: 바이브요.
288 포로미: 새벽 세시쯤인데   → 289 이재언: 새벽 세 시요.
313 포로미: 아 카레          → 314 이재언: 카레요.
438 포로미: 보통은           → 438 이재언: 보통이요.
530 포로미: 북해도... 푸딩    → 531 이재언: 북해도 푸딩.
```

**받은 말을 한 번 되뇌고 나서 대답을 시작하는 것이 이 인물의 기본
동작이 됐다.** 한두 번이면 「곱씹는 사람」인데, 80번이면 틀이다.

### 민현 — 「X 아니고요」로 되받기 53회

```
957   권력은 아니고요.        980   꼬맹이는 좀 아닌데요.
997   도시락 아니고요.        1026  각별한 거 아니고요.
1062  치매는 아니고요.        1085  사과는 아니고요.
1130  말꼬투리 아니고요.      1150  쪼끄만 게 아니고요.
1154  이래라저래라 아니고요.  1166  거짓말 아닌데요.
1248  사춘기 늦게 온 거 아니고요.
1330  꿇은 거 아니고요.       1334  구라 아니거든요.
```

민현은 **유저 말을 부정하면서 시작하는 것**이 기본값이 됐다. 설정의
「진심을 협박의 형태로 포장한다」가 「일단 아니라고 하고 본다」로
번역된 것이다. 둘은 다르다.

## ③ 「우기지 않는다」 규칙이 깨진 자리

프롬프트에 넣어둔 규칙인데, 교과서적으로 위반한 구간이 있다.

```
1095  이민현: 이따 저녁에 밥 먹을 거잖아요, 삼촌이랑.
1103  이민현: 저는 저랑 삼촌이 같이 먹는다고 한 건데.
1106  이민현: "이따 봐요"는 제가 선생님이랑 밥 먹을 거란 뜻이었어요.
```

**같은 말을 세 번 다르게 주장한다.** 그러고는 유저 쪽이 틀렸다고 한다.

```
1104  이민현: 선생님이 왜 자꾸 삼촌이랑 저를 헷갈려요.
1108  이민현: 왜 자꾸 저랑 삼촌을 헷갈려요, 선생님.
```

한 번은 우겨도 캐릭터지만, 자기가 한 말을 바꿔놓고 상대를 탓하는 것은
「진심을 협박으로 포장하는 애」가 아니라 그냥 상대를 지치게 하는
사람이다. 유저 쪽 발화가 1113에서 「뭐라는거야...」로 무너진다.

같은 구간에서 **한 문장을 여덟 번 반복**한다 — 「수업 들어가요」가
994·1016·1024·1047·1051·1064·1068·1072·1076에 있는데 그러고도 계속
대화한다. 나가겠다고 말하는 것이 대화를 끝내는 장치가 아니라
말버릇이 됐다.

## ④ 재언 말투가 한 대화 안에서 갈린다

관전(조카와 단둘)에서 반말과 존댓말이 문장마다 바뀐다.

```
2770  냄비에 있어요. 뜨거우니까 조심하고.     ← 존대 + 반말
2774  짧을 일이니까요. 밥 먹고 가요.
2776  차 조심해라.                          ← 반말
2778  여분이야.                             ← 반말
2782  챙겨.                                 ← 반말
2786  수업 없어?                            ← 반말
2798  밥 먹어요.                            ← 존대
```

삼촌이 조카에게 쓰는 말이 정해져 있지 않다. 이 인물은 「정돈이 갑옷」인
사람이라 말투가 흔들리는 것 자체가 설정과 어긋난다. 둘 중 하나로
고정해야 한다 — **반말 쪽이 관계에 맞는다.**

같은 자리에서 1:1 방은 계속 존댓말이므로, 방마다 다른 것이 아니라
**한 방 안에서 섞이는 것**이 문제다.

## ①은 고쳤다

`parseMessages`가 첫 「{」부터 **문자열 끝까지** 잘라서 파싱하고 있었다.
뒤에 뭐가 하나라도 붙으면 — 닫는 백틱 하나든 모델이 덧붙인 설명이든 —
`JSON.parse`가 터지고, 마지막 폴백이 **원문을 통째로 말풍선으로** 만들었다.
13회 누출의 정체가 그 한 줄이다.

| 고친 것 | 어떻게 |
|---|---|
| JSON·코드펜스 누출 | `carveJson`이 중괄호 짝을 세서 거기까지만 자른다. 문자열 안의 중괄호와 이스케이프를 센다 |
| 모델 사고 과정 노출 | 파서가 다 실패했을 때 구조가 비치면(`{`·`"messages"`·코드펜스) 빈 목록을 돌려보낸다 |
| 제 이름을 호칭 자리에 | `dropMeta`가 제 이름과 짧은 조사뿐인 말풍선을 버린다. 문장 안의 제 이름은 안 건드린다 |
| 한자가 단어를 깨뜨림 | 한자가 한글에 **붙어** 있으면 단어 안에 낀 것이므로 그 말풍선을 버린다. 떨어져 있으면(「那, 도서관」) 예전처럼 지우기만 한다 |

시험 12개를 새로 걸었다.

```
ok  닫는 백틱이 붙어도 읽는다
ok  JSON 뒤에 모델이 덧붙인 말이 있어도 읽는다
ok  코드펜스로 감싸도 읽는다
ok  모델의 사고 과정은 안 내보낸다
ok  안 닫힌 JSON 조각도 안 내보낸다
ok  평범한 한 줄은 그대로 나간다
ok  단어에 낀 한자는 그 말풍선을 버린다
ok  제 이름만 있는 말풍선은 버린다
ok  문장 안의 제 이름은 안 건드린다
```

남은 것은 ⑤ 메아리와 ⑦ 민현의 「아니고요」 둘이다. 둘은 사실 한 뿌리다 —
유저의 말을 집어다 뒤집는 것이라, ⑤를 어디까지 막을지 정해야 ⑦도 정해진다.

## 되짚은 것 두 가지

### 「빈 목록은 화면에 실패를 띄운다」 — 그렇지 않았다

위에 그렇게 적어뒀는데 확인해보니 아니었다. 워커는 빈 목록을 **200으로**
돌려주고, `app.js`는 이렇게 받는다.

```js
if(list.length) enqueue(bucket,list);
else setBusy(b=>({...b,[bucket]:false}));   // 스피너만 끈다
```

`setFailed`는 HTTP 오류일 때만 세워진다. 그래서 빈 목록은 재시도 버튼이
아니라 **조용히 죽은 턴**이었다 — 유저는 답이 안 온 줄도 모른다.
한자에 깨져서 한 줄짜리 답이 통째로 사라지는 자리도 여기로 떨어졌다.

걸러내고 나서 남은 것이 없으면 502로 돌린다. 자는 사람이라 지운 것은
빼고 본다 — 그건 뜻이 있는 빈 손이다.

### 「유저 이름 치환이 제 이름을 집었다」 — 틀린 진단이었다

그런 코드 경로가 없다. `{user_name}`은 `body.user_name`으로만 치환되고
인물 이름이 거기 들어갈 길이 없다. 치환 버그가 아니라 「선생님도요」 틀을
잘못 베낀 것이고, 뿌리는 ②번 메아리다. `isSelfName`은 증상을 덮는 것이라,
메아리를 제대로 잡으면 없어져야 한다.

### 영어를 세는 것은 걷어냈다

`LEAKY`가 영어 문구 넷(`The instructions` `I should` `Let me` `JSON`)을
표로 막고 있었다. 기록에 나온 그 한 줄만 막혔고 「Looking at the context」
「Based on」 「Given that」는 그대로 샜다. 비율로도 재봤는데 이번에는
「Wolf Alice 좋아해요?」가 사라졌다 — 이 둘은 노래 제목과 상표를 말할 수
있어야 한다.

무슨 말로 쓰였는지로 가르지 않는다. 구조가 비치는 것만 본다. 13회 누출의
진짜 원인은 `carveJson`이 고쳤고, 영어 사고 과정 한 줄도 같은 파싱 실패에서
나온 것이다. 그래도 평문으로만 답한 턴은 여전히 통과한다 — 남은 구멍이다.

## ②의 범위를 좁혔다

「메아리 133회」로 세어둔 것 중 실제로 막을 것은 **「-(이)래요」로 받는 것**
하나다. 작가 판단이다.

```
(x) 유저: 흥 → 「흥이래요.」
(o) 유저: 각종 댄스 가능 → 「각종이요? 어떤 거요.」
(o) 유저: 학교에 비리로 수영장 만들어줘 → 「비리로 수영장을요.」
```

받아서 되묻는 것은 대화다. 되뇌고 끝나는 것이 메아리다. 그래서 재언의
「두통이요 → 두통이구나.」 80회도 그 자체로는 결함이 아니다 — 다만
「김밥 좋아하는구나.」처럼 **되뇌고 끝나는** 예시는 다음을 여는 쪽으로 고쳤다
(「또 뭐 좋아해요?」).

코드는 처음부터 맞게 돼 있었다. `dropEcho`의 `QUOTE_BACK`이 보는 것은
`래요|래|라뇨|라니요|라니|랍니다|랍니까`뿐이다. 규칙 문장만 코드보다 넓게
적혀 있었고, 검수도 그 넓은 문장을 기준으로 세었다.

민현의 「아니고요」 53회는 아직 판단이 안 나왔다.

| 어디 | 뭐라고 |
|---|---|
| `JAEEON` 말투 | 「이민현에게는 반말을 쓴다」 뒤에 **한 대화 안에서 섞지 않는다**를 붙였다. 기록에서 그대로 집어온 「밥 먹어요」와 「차 조심해라」를 예시로 박았다 |
| `FORMAT_AUTO` | 「이 방에는 존댓말을 쓸 상대가 없다」. 유저가 없는 자리인데 1:1방의 해요체가 흘러온 것이므로, 상대가 없다는 것부터 말한다 |

관전방은 `FORMAT_AUTO`를 저 혼자 쓴다. 세 번째 캐시 덩어리 맨 앞이라
재언방·단톡방 캐시는 안 건드린다. 인물 블록은 한 번 다시 쓰이지만
그건 세 방이 다 같이 겪고 한 번으로 끝난다.

시험 둘을 걸었다.

```
ok  재언은 조카에게 반말로 고정이다
ok  관전방에는 존댓말 쓸 상대가 없다
```

## 자리에 어떻게 갔는지를 안 보내고 있었다

베타 기록에는 없던 자리인데, 유저가 잡아서 적는다.

```
레코드샵 (「같이 갈 사람은 Who?」로 재언을 골라 같이 감)
이재언: 여기까지 어떻게 왔어요.
이재언: 오는 길에 들렀어요?
이재언: 저도 지나가다 들어왔어요.
```

워커는 자리 **이름**만 받고 있었다. 그래서 임자가 없는 자리는 전부

```
따로 만난 자리다. 둘 다 여기까지 왔다.
```

로 깔렸다. 나란히 걸어 들어온 사람한테 「지나가다 들어왔다」고 말하게
만든 것은 모델이 아니라 이 한 줄이다.

프론트는 세 갈래를 다 알고 있었다. 그걸 `came`로 같이 보낸다.

| 어떻게 갔나 | `came` | 자리에 뭐라고 적히나 |
|---|---|---|
| 인물이 가자고 했고 유저가 응했다 | `invited` | 네가 가자고 해서 둘이 같이 왔다 |
| 유저가 동행을 골라 갔다(도서관·레코드샵) | `asked` | {user_name}이 같이 가자고 해서 둘이 같이 왔다 |
| 같이 있다가 자리를 옮겼다 | `asked` | 〃 |
| 혼자 찾아갔거나 마주쳤다 | 없음 | 예전 그대로 |

**자리에 있는 내내 보낸다.** 첫 턴에만 보내면 두 번째 말부터 도로
남남이 된다 — 그래서 자리(scene)에 적어두고 자리째 딸려 보낸다.
「같이 갈 사람은 Who?」로 고른 자리는 지문도 「{이름}과 레코드샵에 갔다」로
남긴다. 이력만 읽는 다음 턴이 혼자 간 것으로 읽지 않게.

제 자리라는 사실은 그대로 둔다. 도착에 관한 줄만 갈아 끼운다 —
같이 걸어 들어왔는데 「찾아온 쪽은 유저다」가 붙으면 또 남남이 된다.

시험 8개를 걸었다. 앱에서는 초대 수락이 자리를 안 여는데(웹은 연다)
그건 원래 있던 차이라 여기서는 안 건드렸다.
